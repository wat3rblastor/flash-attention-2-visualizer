An interactive walkthrough · FlashAttention-2 (Dao, 2023)

Attention is memory-bound.
FlashAttention fixes the memory, not the math.

Exact attention — same output, no approximation — computed without ever materializing the N×N attention matrix in GPU memory. This page walks the algorithm from the FlashAttention-2 paper one block at a time, with real numbers you can step through.

01 · The problem

The N×N matrix doesn't fit where the compute lives

Standard attention computes, for each head:

S = Q·Kᵀ (N×N scores)  →  P = softmax(S) (N×N weights)  →  O = P·V (N×d output)

The trouble is the intermediates. At sequence length N = 8192, S and P are each 8192 × 8192 ≈ 67 million floats per head. A GPU has two kinds of memory to put them in:

SRAM (on-chip, per SM)

192 KB
≈ 19 TB/s on an A100 — right next to the compute units
⇆

HBM (off-chip DRAM)

40–80 GB
≈ 1.5–2 TB/s — big, but ~10× slower to reach

S and P only fit in HBM. So the standard kernel writes 67M scores out to slow memory, reads them back for the softmax, writes the weights out again, and reads them back for P·V. The GPU's matmul units spend most of their time waiting on memory traffic, not multiplying.

FlashAttention's move: cut Q, K, V into blocks small enough that a block of each — plus a running output block — fits in SRAM at once. Compute attention tile by tile, keep every intermediate on-chip, and never write S or P to HBM at all. The only obstacle is the softmax, which normally needs a whole row before it can normalize anything. Section 03 shows the trick that removes that obstacle; first, watch the algorithm run.

02 · The algorithm, live

The whole forward pass is thirteen lines

You know the formula — O = softmax(QKᵀ/√d)·V. Here is the complete algorithm that computes it without materializing anything N×N. Setup: split the N rows of Q into blocks Q₀…QT−1 of B rows each, and likewise K and V into column blocks; one worker (thread block) runs the loop below for its own Q block, holding O, m, ℓ in registers the entire time. The listing on the left is the real control flow — press play and watch the current line execute, on a toy problem small enough to see every number: N = 16, d = 4, B = 4, so T = 4 and the attention matrix is a 4×4 grid of tiles.

Things to notice as it runs: the S tile appears and disappears — the "S/P tiles written to HBM" counter stays at zero forever. When a new K block contains a larger score than anything seen so far, the running max m jumps, and everything already accumulated gets rescaled by one multiply — that's the online softmax at work. And O touches HBM exactly once per Q block, at the very end.

03 · The enabling trick

Online softmax: normalizing a row you haven't finished reading

Softmax looks like it needs the whole row first — you can't divide by the sum of exponentials before you've seen every score, and for numerical stability you subtract the row max, which you also don't know yet. The fix is to keep two running statistics per row and repair the past whenever the future surprises you:

mnew = max(mold, max(new scores))
ℓnew = e^(mold − mnew) · ℓold + Σ e^(sᵢ − mnew)
— the red factor rescales everything accumulated so far to the new reference max

In the full algorithm the same correction factor e^(mold − mnew) also multiplies the output accumulator Oacc, since every previously-added term e^(s − mold)·v carries the old reference max. That's the rescale you saw flash in section 02. The division by ℓ happens once, at the very end — one of FlashAttention-2's tweaks over v1, which divided as it went.

04 · What v2 changed

Swap the loops, and the accumulator stops commuting

FlashAttention-1 put the K/V loop outside: fix a K/V block, then visit every Q block. But the running state (O, m, ℓ) belongs to rows — to Q blocks. Visit the tiles column-by-column and each Q row's accumulator must be written back to HBM and re-read on every single visit. Visit them row-by-row (FA-2) and the accumulator just stays in registers. Race them:

FlashAttention-2

outer loop over Q (rows) · O lives in registers
O-accumulator HBM traffic:

Fewer non-matmul FLOPs

GPUs do matmuls ~16× faster than everything else, so scalar work is precious. FA-2 keeps O unnormalized until the final step (one division per row instead of one per block) and stores a single statistic L = m + log ℓ for the backward pass instead of both m and ℓ.

Parallelism over sequence length

FA-1 launched one thread block per (batch × head) — too few to fill a GPU for long sequences at small batch. Because FA-2's Q blocks are independent, it also parallelizes across the row dimension, keeping all SMs busy even at batch size 1.

Better warp partitioning

Within a thread block, FA-1 split K/V across warps — each warp got a partial result, which needed shared-memory writes and a synchronized reduction ("split-K"). FA-2 splits Q across warps: each warp owns whole rows, so no communication at all.

Net effect: ~2× faster than FlashAttention-1, reaching 50–73% of the A100's theoretical peak FLOPs — on exact attention.

05 · Why it scales

The payoff grows with sequence length

Standard attention moves Θ(N²) values through HBM; FlashAttention moves Θ(N²d²/M), where M is SRAM size — and since M ≫ d², that's far less. Crucially, memory also stops being the thing that caps N: nothing of size N² is ever stored, so memory use is linear in N. Drag the sliders (fp16, d = 64, one head):

— less HBM traffic — and the N×N matrix ( it would occupy) is never allocated at all.

Longer sequences widen the gap: standard traffic grows with N² while the N² term in FlashAttention is divided by M/d² (how many times a K/V pass fits in SRAM). Bigger SRAM → bigger blocks → fewer passes over K and V. This is also why the technique matters more every hardware generation: compute keeps growing faster than memory bandwidth.
