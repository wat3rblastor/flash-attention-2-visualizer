Attention is memory-bound.
FlashAttention fixes the memory, not the math.

Exact attention — same output, no approximation — computed without ever building the N×N attention matrix. This page covers the four things you need to know first, then walks the algorithm line by line with every number computed live. Based on the FlashAttention-2 paper.

Part one

Background

Four ideas. You know the attention formula already — what you need on top of it is the shape of the intermediates, where a GPU can physically put them, how to cut a matmul into blocks, and the one trick that lets softmax be computed in pieces. Then the algorithm reads like a consequence.

Background 01 · The shapes

Two of attention's four matrices are N×N

Attention is three steps, and the middle two produce something much bigger than what goes in:

S = Q·Kᵀ / √d N×N  →  P = softmax(S) N×N  →  O = P·V N×d

Q, K, V and O are all N×d — long and thin, since the head dimension d is small (typically 64 or 128) and fixed. S and P are N×N — square, and growing quadratically. Drag N and watch what happens to their relative size (drawn to scale):

Takeaway: the inputs and the output are linear in N. Only the two intermediates are quadratic — so if you could avoid ever holding S and P whole, attention's memory footprint would be linear. That is exactly what FlashAttention does.
Background 02 · Where matrices live

A GPU has a small fast memory and a big slow one

"Memory" on a GPU is two very different things, and the gap between them is the whole story:

SRAM (on-chip, per SM)

192 KB
≈ 19 TB/s on an A100 — sits right next to the compute units
⇆

HBM (off-chip DRAM)

40–80 GB
≈ 1.5–2 TB/s — roomy, but ~10× slower to reach

At N = 8192 in fp16, one head's S matrix is 134 MB. SRAM is 192 KB. It is off by roughly 700× — S has no choice but to live in HBM. So the standard kernel writes 67M scores out to slow memory, reads them back to softmax them, writes the weights out, and reads them back again for P·V. Four round trips through the slow path, moving data that is only ever used once.

Meanwhile the tensor cores that do the actual multiplying sit idle waiting. That's what memory-bound means: the bottleneck isn't arithmetic, it's bandwidth. Making attention faster is a matter of moving less, not computing less.

Takeaway: any plan that writes an N×N matrix to HBM has already lost. The goal is to keep every intermediate on-chip — which means working on pieces small enough to fit in 192 KB.
Background 03 · Tiling

A matmul can be computed one tile at a time

Cut the N rows of Q into blocks of B rows: Q₀, Q₁, … Do the same to K and V. Now a single B×B tile of S is just one small matrix product:

Sij = Qi · Kjᵀ / √d — needs only block i of Q and block j of K

This is ordinary matmul blocking, nothing specific to attention yet. The important part is what it costs: computing tile (i, j) requires only two B×d blocks on chip, never the full matrices. Click a tile to see where it comes from:

Real kernels use B ≈ 128, not 4. The sizes above are for that realistic block size: four blocks plus the output accumulator comfortably fit on-chip, which is what sets B in practice — blocks are chosen as large as SRAM allows.

Takeaway: S never has to exist all at once. One tile at a time is enough — if you can also apply softmax one tile at a time. That's the one remaining obstacle, and it's the next section.
Background 04 · Online softmax

Softmax can be computed in pieces, exactly

Softmax is what makes attention resist tiling. For one row of scores it is

softmax(s)i = e^(si − m) / Σj e^(sj − m)  where m = max(s), subtracted for numerical stability

Both m and the denominator depend on the entire row. If you only have the first block of scores, you don't know the max yet, and you don't know the sum — so you can't produce a final weight for anything. A tile-at-a-time kernel seems impossible.

The way out is to keep two running statistics per row and repair the past when a bigger score shows up later:

m′ = max(m, max of new block)
α = e^(m − m′) — correction factor for everything already accumulated
ℓ′ = α·ℓ + Σ e^(si − m′)

One row, eight scores, arriving in two blocks of four. Bar height is each score's weight e^(s − m); watch what the second block does to the first:

Takeaway: the rescale by α is the entire trick. It costs one multiply and it makes block-wise softmax mathematically identical to the real thing. The same α also multiplies the output accumulator, since every term already added to it carries the stale max.

Part two

The algorithm

Everything above assembles into one loop nest. Tiling says you can work on a B×B piece of S at a time; online softmax says you can fold each piece into the output immediately and still be exact; the memory hierarchy says to do all of it without touching HBM in between.

The forward pass

Thirteen lines, and you've seen the reason for each one

One worker handles one Q block: it loads that block once, sweeps across every K/V block, and keeps its output accumulator O plus the statistics m and ℓ in registers for the whole sweep. Nothing N×N is ever written anywhere. Press play — the highlighted line is the one executing, and every number is computed live on a toy problem small enough to read: N = 16, d = 4, B = 4.

Algorithm · one worker
1for i = 0 … T−1:
2 load Qi HBM→SRAM
3 m ← −∞; ℓ ← 0; O ← 0
4 for j = 0 … T−1:
5 load Kj, Vj HBM→SRAM
6 S ← Qi·Kjᵀ / √d
7 m′ ← max(m, rowmax S)
8 P ← exp(S − m′)
9 α ← exp(m − m′)
10 ℓ ← α·ℓ + rowsum P
11 O ← α·O + P·Vj; m←m′
12 O ← O/ℓ; L ← m + log ℓ
13 write Oi, Li SRAM→HBM

Line 12's L is the logsumexp — the backward pass needs it to rebuild P.

Part three

What it bought, and what v2 changed

The algorithm above is FlashAttention-2. The original FlashAttention had the same core idea with the loops the other way around — a small-looking difference with a large cost.

Payoff 01 · Memory traffic

Less moved, and nothing quadratic allocated

Standard attention moves Θ(N²) values through HBM. FlashAttention moves Θ(N²d²/M), where M is SRAM size — and since M ≫ d², that's dramatically less. It also never allocates anything N×N, so memory use is linear in N and sequence length stops being capped by attention's footprint.

— less HBM traffic — and the N×N matrix ( it would have occupied) is never allocated at all.

Larger SRAM means larger blocks, which means fewer passes over K and V — that's the M in the denominator. And the gap widens with N, which is why this matters more every hardware generation: compute keeps outgrowing bandwidth.

Payoff 02 · Version 2

Swap the loops, and the accumulator stops commuting

FlashAttention-1 put the K/V loop outside: fix a K/V block, then visit every Q block. But the running state (O, m, ℓ) belongs to rows — to Q blocks. Sweeping column by column means each Q block's accumulator must be written back to HBM and re-read on every visit. Sweeping row by row, as in the algorithm above, lets it stay in registers. Same tiles, same math, very different traffic:

FlashAttention-1

outer loop over K/V (columns) · O bounces to HBM
O-accumulator HBM traffic:
0 block reads + writes

FlashAttention-2

outer loop over Q (rows) · O lives in registers
O-accumulator HBM traffic:
0 block writes, ever

Counting one read plus one write of the O block per tile visit for v1, against one write per finished Q block for v2 — a simplification of the real kernel, but the asymptotics are the point.

Fewer non-matmul FLOPs

GPUs run matmuls roughly 16× faster than other arithmetic, so scalar work is expensive in relative terms. v2 keeps O unnormalized until line 12 — one division per row for the whole sweep instead of one per block — and saves the single statistic L rather than both m and ℓ.

Parallelism over sequence length

v1 launched one thread block per (batch × head), too few to fill a GPU at long sequence and small batch. Since v2's Q blocks are independent, it also parallelizes across rows, keeping every SM busy even at batch size 1.

Better warp partitioning

Inside a thread block, v1 split K/V across warps, so each warp held a partial result that needed shared-memory writes and a synchronized reduction. v2 splits Q across warps — each warp owns whole rows and needs no communication at all.

Together: about 2× faster than FlashAttention-1, reaching 50–73% of an A100's theoretical peak FLOPs — on exact attention, with no approximation anywhere.
