FlashAttention, step by step · part 2

The backward pass: gradients through a matrix you threw away

The forward pass never stored the attention weights P — that was the whole point. Now training needs ∂L/∂Q, ∂L/∂K, ∂L/∂V, and every one of them involves P. The backward pass rebuilds each tile of P from two small saved artifacts, exactly, and never materializes anything N×N. Same deal as before: real numbers, one block at a time.

01 · The setup

What backward needs, and what forward actually saved

Given the upstream gradient dO = ∂L/∂O, the chain rule through O = P·V, P = softmax(S), S = Q·Kᵀ/√d demands:

dV = Pᵀ·dO     dP = dO·Vᵀ     dS = (softmax Jacobian)·dP
dQ = dS·K / √d     dK = dSᵀ·Q / √d

Both P and dP are N×N. Storing P in the forward pass would reintroduce the O(N²) memory and HBM traffic that FlashAttention exists to avoid. Instead, the forward pass saved exactly two things per head:

O the output

N × d

Needed downstream anyway — free to keep.

L = m + log ℓ

N values

One logsumexp per row: the running max and normalizer from the online softmax, fused into a single number.

P, the attention weights

N × N

Never stored. 67M floats per head at N=8192 — this is the thing we refuse to keep.

Recomputation. L makes P cheap to rebuild. For any tile, softmax(S)ᵢⱼ = e^(Sᵢⱼ − mᵢ)/ℓᵢ = e^(Sᵢⱼ − mᵢ − log ℓᵢ), so:

P = exp( Qi·Kjᵀ/√d − Li ) — one matmul, one exp. Exact, not approximate.

No second softmax pass, no new max-finding, no normalization step — L already encodes both. Any 4×4 tile of P can be conjured in SRAM on demand from Qi, Kj, and four saved scalars.

02 · The second trick

dS without the softmax Jacobian

The Jacobian of a softmax row is the N×N matrix diag(p) − p·pᵀ. Applying it naively to dP would mean another huge intermediate. But multiply it out for one row:

dS = (diag(p) − p·pᵀ)·dp = p ∘ dp − p·(pᵀ·dp) = p ∘ (dp − pᵀ·dp)
and the scalar pᵀ·dp = pᵀ·(Vᵀ·dOᵢ)... wait — rearrange: pᵀ·dp = (pᵀV)·dOᵢ = Oᵢ·dOᵢ

That scalar — the row's share of the Jacobian correction — collapses to a dot product of two things we already have in HBM: the saved output row and its upstream gradient. Define, per row:

Di = rowsum(dOi ∘ Oi) (N scalars, precomputed in one cheap kernel before the main loop)
dS = P ∘ (dP − Di) — elementwise; the N×N Jacobian never exists

So the entire backward pass reduces to tile-sized matmuls and elementwise ops, fed by recomputed P tiles and one precomputed length-N vector D. Everything fits the same SRAM-resident, tile-at-a-time mold as the forward pass.

03 · The algorithm, live

FlashAttention-2 backward pass, block by block

Same toy problem as the forward page: N = 16, d = 4, block size B = 4 — but the loops swap roles. Backward puts the K/V loop outside: each worker owns one K/V column block, accumulates its dKj and dVj in SRAM across all Q blocks, and writes them once. (dKj and dVj gather contributions from a whole column of tiles — the exact mirror of why forward's O wanted rows.) The price: dQ now gathers across the row, so workers add into it in HBM atomically. Things to notice: the recomputed P tile is bit-identical to the one forward discarded — L makes that a one-liner, and the "P tiles ever stored" counter stays at zero across both passes. dKj and dVj never touch HBM until their column is finished — one write each, mirroring forward's O. And every inner step ends with an atomic add into dQ: with one worker per column running in parallel, all four of them contribute to the same dQi rows, so the hardware has to serialize those additions.

04 · The bargain

Recomputation: paying FLOPs to dodge memory

Backward recomputes every S and P tile that forward already computed once — genuinely extra arithmetic. It's still a win, and decisively: the alternative is reading an N×N matrix back from HBM, and on modern GPUs the matmul units sit idle waiting for exactly that kind of traffic. FLOPs are the abundant resource; bandwidth is the scarce one.

The FLOP bill

Standard attention backward is already ~2× forward's work (5 big matmuls — dV, dP, dQ, dK, plus recompute-free S — vs forward's 2). FlashAttention adds S and P recomputation on top: about 2.5× forward. Measured end-to-end, it still beats materialization.

Memory stays linear

Backward's working set is O, L, D, dO, and the gradients — all N×d or N. Nothing N×N is ever allocated in either pass, so sequence length is bounded by compute budget, not memory.

What it reaches

FA-2's backward hits ~63% of the A100's theoretical peak FLOPs — lower than forward's 50–73% band's top end (the atomics and extra loads cost something), but ~2× FlashAttention-1's backward.
